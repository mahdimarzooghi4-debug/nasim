# DC-020 — پیش‌نویس معیارهای صلاحیت و فعال‌سازی Provider برای تصویب مدیر عملیات نسیم

**Status: DRAFT FOR MANAGER DECISION — NOT ACTIVE POLICY.** تاریخ: 2026-10-09. مجوز تهیه: D-0168. مرجع انسانی تصمیم: مدیر عملیات نسیم (D-0157). مبنا: BC-008، DC-007، D-0036…D-0042، D-0131…D-0133.

این متن **چک‌لیست تصمیم/پیشنهاد** است؛ نه معیار الزام‌آور، نه سند صادرشده توسط مدیر عملیات، نه اجرای فعال‌سازی. ثبت Provider و مدارک صرفاً Candidate/ Evidence/ Review Request تولید می‌کند.

## ۱. صلاحیت پیشنهادی پیش از تصمیم
- **هویت و نمایندگی:** روش احراز هویت حقوقی/حقیقی و اختیار امضای نماینده؛ اعلام مسئول بررسی و منبع واقعی اعتبارسنجی (OPEN).
- **حوزه خدمت:** Service family/item مجاز، محدوده جغرافیایی، پوشش عملیاتی، نوع Provider و نیازمندی رشته تخصصی هر خدمت (OPEN).
- **مدارک حرفه‌ای:** نوع مجوز یا گواهی معتبر برحسب رشته، صادرکننده، تاریخ اعتبار، قواعد انقضا و مرجع استعلام؛ هیچ نوع مجوز پیش‌فرض تصویب نمی‌شود (OPEN).
- **قرارداد و تعهدات:** اصل قرارداد، مسئولیت حرفه‌ای، محرمانگی، تبادل حداقلی داده، حقوق سالمند و شروط تعلیق/خاتمه با مرجع بررسی حقوقی واقعی (OPEN).
- **امنیت/داده:** مجوز sharing به ازای Purpose و Service؛ Provider به Full Case دسترسی پیش‌فرض ندارد؛ آموزش AI از داده Provider مجوز جدا می‌خواهد.
- **کیفیت خدمت:** Evidence لازم برای خدمت/انجام یا عدم انجام، مسئول بررسی، فرایند شکایت و مسیر جبران/پیگیری؛ score/threshold و SLA بدون تصمیم مستقل ممنوع.
- **ظرفیت:** روش اظهار ظرفیت، دامنه خدمت/منطقه، اعتبار اظهار و کنترل ظرفیت در تغییرات (OPEN).
- **آمادگی عملیات:** کانال تماس عملیاتیِ معتبر، پاسخ‌گویی به ارجاع، روش ثبت accept/decline و برخورد با no response (OPEN).

## ۲. Decision authority و حد اختیارات
1. **ثبت Candidate → دریافت شواهد → درخواست Review** مراحل فعلی فاقد قدرت فعال‌سازی‌اند.
2. تصمیم **Qualification** فقط با اقدام انسانی مدیر عملیات پس از رسیدگی به مدارک معتبر، معیارهای مصوب و Scope دقیق انجام شود؛ Rule و State Machine هنوز به تصویب نیاز دارند.
3. **Activation** یک تصمیم انسانی جدا از Qualification با Service/Geography/Contract scope و effective/version است؛ state/مکانیزم و شرایط باید تصویب شوند. AI و System هرگز خودکار فعال نکنند.
4. انتخاب Provider برای Referral با مدیر عملیات است، مستقل از داشتن Qualification/Activation؛ رضایت/permission، Service eligibility و وضعیت فعلی الزامی است.
5. رد، عدم ظرفیت یا عدم پاسخ Provider، Closure موفق یا Need Resolution خودکار تولید نمی‌کند.

## ۳. موارد درخواست تصویب مدیر عملیات — پاسخ به صورت یک بسته
برای نخستین Service واقعی لطفاً نوع و Service scope، مدارک الزامی هر نوع Provider و مرجع راستی‌آزمایی، نام Role انسانی بررسی/امضا، شرط قرارداد و Data Sharing، شروط حداقل فعال‌سازی، قواعد پاسخ/رد/timeout، Completion Evidence، Suspension/Revocation و Case handoff را با نسخه و اثر زمانی مشخص تصویب یا Defer کند. برای هر موضوع **ACCEPT/ MODIFY/ DEFER/ REJECT** و Evidence/Owner ثبت شود. بدون این قراردادها Code هیچ Activated Provider یا Dispatch واقعی ایجاد نمی‌کند.

## ۴. ممنوعیت‌ها
هیچ ranking، حدنصاب عددی، SLA، Provider Type رسمی، جریمه، tariff، billing، انتخاب خودکار AI، شهر/منطقه پیش‌فرض، consent یا فیلد Case قابل‌اشتراک در این پیش‌نویس «مصوب» نیست. Backend فعلی صرفاً Evidence و Review Request توصیفی دارد.
