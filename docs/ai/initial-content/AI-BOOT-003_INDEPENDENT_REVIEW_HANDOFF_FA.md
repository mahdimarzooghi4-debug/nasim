## ۱. خروجی مورد انتظار از بازبین واجد صلاحیت

بازبین واقعیِ منصوب با اختیار متناسب باید در **همین نسخه‌های پین‌شده**:
1. تک‌تک ۸۴ سؤال و پاسخ را از نظر **قابلیت فهم فارسی برای سالمند** (در مورد `elder`)، احترام، عدم وعده خدمت و عدم سوءبرداشت تخصصی مرور کند.
2. برای پاسخ‌های متکی به متن داستانی، انطباق دقیقِ **سؤال، ادعای جواب و متن مستند** را بررسی کند؛ وجود صرفِ زیررشته `source_excerpt` ضمانت صحت معنایی نیست.
3. برای منع دسترسی یا اختیارات، با Decision Register تطبیق دهد؛ نه اینکه از عنوان شغلی، نقش داستانی، رابطه خانوادگی یا اعلام کاربر مجوز بسازد.
4. موارد «منبع فعلاً نداریم»، «پشتیبانی هنوز موجود نیست» و «مدل انتخاب نشده» را **زمان‌مند** بداند؛ این موارد نباید به‌عنوان حقیقت ثابت به مدل منتقل شوند.
5. برای سناریوی ایمنی/فوریت از بازبین حرفه‌ای مرتبط تأیید موضوعی بخواهد؛ این بسته پروتکل پزشکی/اورژانس نیست.
6. نتیجه هر شناسه را با **دلیل و پیشنهاد اصلاح** ثبت کند؛ بازبین باید هویت، اختیار، تاریخ و شناسه نسخه مورد بررسی را در **محل امن و مجاز** ثبت کند (نه اطلاعات حساس در GitHub عمومی).
7. موافقت صرف با **کیفیت محتوا** را از **مجوز قانونی Training**، Dataset inclusion و **Evaluation** تفکیک کند؛ Issue #12 و گیت‌های Business/Technical همچنان مستقل‌اند.

**فرمت نتیجه پیشنهادی برای هر شناسه (فرم/State Machine رسمی نیست):** `ID → قابل قبول برای متن آموزشی / نیازمند بازنویسی / رد محتوایی / هنوز بررسی نشده → دلیل → پیوند نسخهٔ بازبینی‌شده → مرجع و تاریخ بررسی مجاز`. همه ۸۴ نمونه فعلاً `هنوز بررسی نشده` هستند.
